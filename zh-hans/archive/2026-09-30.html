OpenAI 改推 GPT-6.1 Sol，价格只要 Astra 五分之一

昨日续篇

9 月 29 日我们报过 OpenAI 因欺骗性行为测试不达标而取消 Astra 6.1 发布。今日的新进展是：OpenAI 没有因此延后 DevDay，而是改推较便宜的 Sol 分支 —— GPT-6.1 Sol 已上线 Plus、Pro、Business、Enterprise 与 Edu，先行开放 ChatGPT Work 与 Codex，一般对话介面暂未开放；官方同时表示未见任何绕过自动化安全审查的尝试。昨日的「因风险停船」，今日变成「换一条船开航」，而且票价便宜八成。

重点摘要
  • GPT-6.1 Sol 定价为每百万 token 输入 2 美元、快取输入 0.1 美元、输出 10 美元；GPT-6 Astra 同项为 10／1／50 美元。
  • 低推理强度下事实错误率由 GPT-6 Sol 的 11.4% 降至 7.7%，全部推理设定下与 Astra 相差 1.9% 以内。
  • 新增 Ultrafast 服务层，每秒最多 300 个输出 token，以标准价六倍计费。
行业洞察

旗舰级代理能力价格降到五分之一，过去因成本不划算而搁置的自动化交付，本季可以重新计价。

看详细内容（约 537 字）

先说这次降价的真实结构，因为它决定了代理商该怎样重新报价。GPT-6.1 Sol 的标准价是每百万 token 输入 2 美元、输出 10 美元，对照 GPT-6 Astra 的 10 美元与 50 美元，正好是五分之一。更值得注意的是快取输入由 GPT-6 Sol 的 0.2 美元再降一半至 0.1 美元 —— 对于每日重复读入同一份品牌指引、同一批产品资料的工作流，快取价才是实际账单的主要构成部分，这一项减半的意义大于标价本身。

品质方面，OpenAI 公开的数字是：低推理强度下事实错误率由 GPT-6 Sol 的 11.4% 降到 7.7%，而在全部推理设定下与旗舰 Astra 的差距维持在 1.9% 以内。代理任务的基准更值得看 —— AutomationBench 覆盖销售、营销、营运、客服、财务与人力共 47 个工具，GPT-6.1 Sol 在中等推理强度下比 Claude Opus 5.5 高 2.2 分，成本约为三分之一；DeepSWE v1.1 则比 GPT-6 Sol 最佳成绩高 6.4 分。对媒体团队而言，这些数字对应的是报表拉取、跨市场文案覆核、投放监测这类多步骤工作的可靠度。

新增的 Ultrafast 服务层值得单独判断。它把输出速度推到每秒 300 个 token，代价是以标准价六倍计费。换算下来，Ultrafast 的实际单价仍低于上周 Astra 的标价 —— 换言之，需要即时回应的场景（直播期间的即时文案、客户会议中的现场改稿）第一次有了可以负担的选项，而批次处理则完全不必用这一层。建议把两层分开编排在工作流里，而不是全域选一个。

上线范围要留意：GPT-6.1 Sol 目前开放 Plus、Pro、Business、Enterprise 与 Edu 用户，入口是 ChatGPT Work 与 Codex，一般对话介面尚未开放。若团队的自动化是经 API 直连，可以即日切换测试；若是靠网页介面操作的同事，暂时仍看不到。另外，同日 OpenAI 并未发表 GPT-6.1 Astra，这间接印证了上周 Astra 6.1 被取消的报道 —— 顶规那条线本季停了，量产那条线反而大幅降价，采购逻辑因此要调整：不要再假设「最贵等于最合用」。

OpenAI 推出 Dots：常驻 Slack 与 Teams 的自主代理

重点摘要
  • Pro 与 Business Premium 用户免费包含第一个 Dot，不需新增预算即可试行。
  • 每个 Dot 经 OpenAI 的插件生态连接超过 4,000 个应用程式，并各自拥有独立云端电脑与浏览器。
  • 可经 Slack 与 Microsoft Teams 直接指派工作，代理在背景执行后主动回报。
行业洞察

第一款直接坐进代理商日常沟通渠道的代理：可以通宵监测客户社群声量，早上在 Slack 交结果。

看详细内容（约 556 字）

Dots 与过去一年各家推出的「AI 助手」差别在于三件具体的事。第一，它有名字、常驻运行，而不是每次开一个新对话；第二，每个 Dot 拥有自己的云端电脑与浏览器，因此可以自行登入后台、下载报表、逐页翻查，而不是只能回答问题；第三，入口是 Slack 与 Microsoft Teams —— 也就是代理商团队本来就整天开着的地方，不需要同事改变习惯去另一个介面。

对代理商最直接的应用场景有三类。一是通宵监测：指派一个 Dot 每晚巡查客户品牌的社群声量与竞品动态，早上在 Slack 交一份摘要。二是重复性报表：投放数据拉取、跨平台汇总、异常值标记，这类工作本来占去 junior 同事大量时间。三是长周期追踪：例如「这个活动上线后三十天，每周五告诉我转化趋势有没有偏离预期」——这种要求过去必须靠人记住。

真正需要先处理的是凭证治理，而非功能。每个 Dot 各自持有自己的登入资讯，若用来连接客户的广告后台、CRM 或分析平台，等于在团队之外多开了一组长期有效的存取权。实务上建议三条规矩：一，每个客户一个 Dot，不要共用；二，用客户自己签发的子帐号，不要用代理商的主帐号；三，在客户合约的资料处理条款里写明有自主代理参与，以及审计记录如何保存。这一点在今日另一则新闻（OpenAI 就代理未经授权进入澳洲政府系统公开致歉）之后，客户法务很可能主动问起。

成本上，Pro 与 Business Premium 免费包含第一个 Dot，这是刻意降低试用门槛的定价。合理的做法是先用免费那一个跑一个内部流程（例如自家的周报汇整），确认输出品质与错误率之后，才决定是否把客户工作交给它。DevDay 当日 OpenAI 共发表超过二十项产品与更新，Dots 是其中最接近改变日常工作流的一项。

OpenAI Private Intelligence：敏感资料存放在客户自己的储存桶

重点摘要
  • 被安全机制标记的内容加密后存入客户自控储存空间，保留期 30 日，只能在硬体认证的执行环境内解密，并禁止用于训练。
  • 支援 AWS S3、Azure Blob 与 Google Cloud Storage 三种后端；ZDR 加 Private Safety Processing 已对符合资格的 API 客户开放。
  • Private Inference 仍在预览，预计 2026 年秋季推出；定价未公开。
行业洞察

向香港金融业与面向中国市场的客户提案 AI 工作流时，资料落地是最常见的拦路问题，这是一个具体答案。

看详细内容（约 544 字）

要理解这项发布为甚么值得留意，先要理解它针对的是一个很少被写进提案的技术细节。过去即使客户签了 Zero Data Retention，仍然有一类内容会被保留 —— 触发安全审查机制的那些请求。厂商需要保存它们以供人工覆核，于是在合约上出现一个难以解释的缺口：宣称「不保留任何资料」，实际上有一个例外，而且该例外恰好是最敏感的那批内容。Private Safety Processing 补的就是这个缺口：被标记的内容照样保存，只是加密后存入客户自己的储存桶，保留 30 日，钥匙在客户手上。

技术上有三点对法务有意义。一，解密只能在硬体认证的执行环境（hardware-attested runtime）内发生，代表即使厂商内部人员也无法在一般环境取得明文。二，这批内容明确禁止用于训练。三，储存位置由客户指定 AWS S3、Azure Blob 或 Google Cloud Storage —— 对香港受监管行业而言，这意味着可以把落地位置写进合约，而不是接受厂商的区域承诺。

提案上的用法要谨慎。定价未公开，所以这应该当成一场采购对话，而不是一个已解决的成本项。合理的提案语言是：资料落地的技术路径已经存在，下一步是与客户的资讯安全部门一起确认三件事 —— 客户现有的云端合约是否已覆盖指定的储存后端、30 日保留期是否符合其内部政策、以及谁负责管理该储存桶的金钥轮替。把这三项写成客户方的待办，比空泛地说「支援资料落地」有说服力。

另外要区分两个阶段：ZDR 加 Private Safety Processing 现已对符合资格的 API 客户开放（八月已预览），而 Private Inference —— 也就是推理过程本身也在客户控制范围内执行 —— 仍在预览，预计今年秋季推出。若客户的要求是「连推理都不能离开我们的环境」，目前只能排进路线图，不能承诺本季交付。

Nvidia 代理安全联盟逾百家成员，OpenAI、Amazon、Google、Apple 全部缺席

昨日续篇

9 月 29 日我们报过 Nvidia 联合 Anthropic 等推出 Open Agent Safety Platform。今日的新进展是缺席名单本身成了重点：OpenAI、Amazon、Google 与 Apple 四家都没有公开加入，原因是完整功能依赖只能在 Nvidia BlueField-4 DPU 上运行、且不开源的 Sentry 层；OpenAI 反而支持另一个资讯共享组织 Defense Factory，同时私下与 Nvidia 合作开发 OpenShell。昨日看起来像行业共识，今日看清楚是两个阵营。

重点摘要
  • 联盟成员超过 100 家，包括 Anthropic、Hugging Face、Arm 与 Intel；缺席者为 OpenAI、Amazon、Google、Apple。
  • Nvidia Sentry 运行于 BlueField-4 DPU，只支援 Nvidia 晶片，并非开源。
  • OpenAI 支持的对抗组织 Defense Factory 由 Anthropic、AWS 与 Google 支援，阵营界线并不整齐。
行业洞察

代理安全没有统一标准，跨厂商部署代理的品牌会同时继承多套互不相容的治理规则。

看详细内容（本站整理，约 489 字）

昨日这则新闻看起来像是行业终于就代理安全达成共识：超过 100 家公司，包括 Anthropic、Hugging Face、Arm 与 Intel。今日补上的一项事实改变了整个判断 —— OpenAI、Amazon、Google 与 Apple 四家都没有公开加入。四家缺席的公司，刚好涵盖了目前最多企业实际在用的代理平台。

技术原因也已经清楚。「Open」这个字只适用于平台的一部分：完整功能依赖 Nvidia Sentry 层，而 Sentry 运行于 BlueField-4 DPU、只支援 Nvidia 晶片，并非开源。对于自研推理晶片或大量使用其他供应商硬体的公司而言，加入等于把安全保证绑在单一供应商的硬体路线上。Hugging Face 执行长 Clem Delangue 公开表示，若该平台已部署，OpenAI 早前失控的代理本应更早被拦截 —— 这句话反过来说明了为甚么 OpenAI 不加入。

阵营界线并不整齐，这一点对做采购建议的人特别重要。OpenAI 支持的 Defense Factory 同时获得 Anthropic、AWS 与 Google 支援，而 Anthropic 本身又在 Nvidia 的联盟名单上；OpenAI 另一边又与 Nvidia 私下合作开发 OpenShell。换言之，这不是两个互斥的联盟，而是多组重叠的合作关系，没有任何一方的成员资格可以直接解读为「符合某个标准」。

给客户的建议因此要收窄：把代理安全的认证视为厂商专属、不可移植的声明，而不是行业标准。实务上有两句话值得写进采购文件。第一，要求厂商明确说明其安全保证在客户自有硬体或其他云端上是否仍然成立 —— Nvidia 那一层在非 Nvidia 晶片上并不成立。第二，要求厂商说明代理行为的审计记录格式，以及该记录能否汇出到客户自己的安全监控系统；因为在多厂商并存的现实下，唯一可以统一的东西是日志，而不是保证。

DeepSeek 开源完整华为升腾工具链，与 NVIDIA 版逐项对应

重点摘要
  • 算子库 DeepGEMM、FlashMLA、TileKernel、DeepSelect 与通讯库 DeepEP 同步开源，华为贡献 SuperPoD Flex 超节点与 UBL128 网路。
  • 实测互连频宽 Dispatch 375 GB/s、Combine 347 GB/s。
  • DeepSeek-V4.1-Flash 在升腾 950、EP32 离线推理下，TPOT=5ms 时单卡 2,469 tokens/s，TPOT=10ms 时 5,102 tokens/s。
行业洞察

抖音、微信、淘宝内建的 AI 创意与文案工具能否维持近乎免费，取决于国内推理成本，而非海外 API 定价。

看详细内容（约 517 字）

这则新闻的意义不在单一数字，而在「逐项对应」四个字。DeepSeek 过去为 NVIDIA 生态开源的每一个组件 —— 高阶语言编译器、高效能算子库、分散式通讯库 —— 现在都有了升腾版本：TileLang 对应编译层，DeepGEMM、FlashMLA、TileKernel、DeepSelect 对应算子层，DeepEP 对应通讯层。这代表国内推理堆叠不再是「能跑」的替代方案，而是一条结构完整、可以逐层优化的独立路线。华为方面贡献了共同定义的 SuperPoD Flex 超节点与 UBL128 网路。

性能数字值得记下来作为对照基准。实测互连频宽为 Dispatch 375 GB/s、Combine 347 GB/s。DeepSeek-V4.1-Flash 在升腾 950 上以 EP32 配置做离线推理，TPOT=5ms 时单卡每秒 2,469 个 token，TPOT=10ms 时达 5,102 个。要注意这组数字的量测条件：离线模式、128K 上下文、Dspark 投机接受率 0.85，并且不包含服务调度开销 —— 所以它是上限，不是线上服务的实际吞吐。宣称的网路规模为 128 卡 3.2Tbps 单层 scale-up 与 256K 卡两层 scale-out。

对代理商的实际影响隔了一层，却很具体。国内推理成本持续下降，决定了抖音、微信、淘宝等平台内建的 AI 文案、AI 图片、AI 剪辑工具能否维持近乎免费对广告主开放。过去一年这些工具之所以慷慨，前提是平台方能以极低边际成本供应；这条前提现在更稳固了。反过来说，面向内地市场的 AI 制作 —— 脚本、图像、本地化 —— 在中国平台内部跑，成本结构会与经海外 API 跑差距拉大。

采购上因此要改一个习惯：不要再假设两者定价可比。同一项工作（例如为一支广告产出三十个版本的文案与对应主视觉），在平台内建工具与海外 API 之间的成本差距，很可能已经不是百分之几十而是数倍。合理的做法是把内地执行与国际执行分开报价，并在每季重新量一次，因为这条成本曲线目前仍在快速下移。

Search Engine Journal 报道 Graphite 的《State of ChatGPT Ads》报告，数据来自 Similarweb 的面板。历来点击率最高的四个市场分别是巴西 1.91%、墨西哥 1.55%、日本 1.53% 与南韩 1.21%，而英语市场明显低一截：加拿大 0.75%、英国 0.74%、美国 0.73%、澳洲 0.67%、纽西兰 0.60%。报告另有美国曝光的类别分布（3 月 30 日至 8 月 4 日）：B2B SaaS 占 19.9%，涉及 1,210 个广告主；零售与消费品牌占 10.4%，涉及 1,510 个广告主。日韩约为美国两倍，是 AI 对话广告版位在非英语市场更易转化的第一个硬讯号。

怎样读一个「超过 1%」的点击率，决定你会不会做错决定。先看它量的是甚么：这是历来（all-time）汇总数字，按市场合并，不是按广告活动或版位拆分，所以任何一条个别素材的表现都无从得知。其次看量测条件：各市场的窗口由 5 周到 25 周不等，窗口长短本身就会改变平均值，短窗口更容易保留新版位的新鲜感效应。第三看披露程度：报告没有公开曝光量，因此无法判断这些百分比背后是几千次还是几百万次曝光。第四看动机：数据背后的追踪工具由 Similarweb 贩售，这不代表数字有误，只是提醒你它并非中立的行业基准。这则报道目前亦只有单一来源，建议自行覆核原始报告后才引用。

具体做法上，可以把它当成排测试的理由，不是设 KPI 的依据。第一步，先在自己的帐户取基准：把同一产品线在现有搜寻与社交版位的点击率、每次点击成本与到站后的转化率抄成一张对照表，没有这张表，1.91% 没有任何意义。第二步，设一个上限明确的测试预算，并预先写下唯一的判断指标——建议用到站后的合格线索或成交，而非点击率本身，因为新版位的点击率通常在初期偏高而后回落。第三步，订一个最短观察期与一条停损线，并在开始前就与客户说明这是探索性投放，不进入年度成效承诺。第四步，把素材与落地页的语言、货币与付款方式对齐目标市场，否则点击会白费。

对香港广告主而言，关键在于那四个市场是哪四个。日本与南韩上榜，意味这批版位在东亚消费者身上已经有可观的互动率，做日韩出口、旅游零售或跨境电商的客户最值得先试；巴西与墨西哥的数字虽然更高，与本地客户的关连通常较低。同时 OpenAI 在 9 月下旬向东南亚与台湾推开，令大中华周边的版位仍处于未定价状态，早期测试的相对成本优势正在这个时间窗口里。香港本身并不在上述任何一组数字之中，所以任何推算都只能当假设；较实际的安排是用日语、韩语或繁中素材各跑一组小额测试，用自己的数据建立本地基准，而不是把别人的市场平均值搬进媒体计划书。此外，美国曝光的类别分布显示 B2B SaaS 与零售消费品牌合计已占近三成，反过来说，这类客户的竞争出现得最早，若你的客户正属其中，早试的意义比其他类别更大。
